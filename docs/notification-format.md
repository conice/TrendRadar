# 推送格式

推送正文使用同一套结构：简短的报告头、分组新闻、AI 解读、末尾备注。新闻标题放在前面，来源、排名和时间另起一行。区域顺序仍由 `display.region_order` 控制，区域开关仍由 `display.regions` 控制。

## 三种报告模式

| 模式 | 报告名称 | 热榜辅助信息 |
| --- | --- | --- |
| `daily` | 当日汇总 | 今日最高排名、采集命中次数、首次至末次观测时间 |
| `current` | 当前榜单 | 最新采样排名；有相邻有效采样时说明较上次的升降或重新上榜 |
| `incremental` | 增量更新 | 本次观测排名、首次发现时间；不重复标注“本轮新发现” |

当日“采集命中次数”表示抓取时发现该条目的次数。排名历史不足时不推断涨跌；没有排名或时间的字段直接省略。跨天重试的条目保留原观测日期。当前模式有快照时间时显示快照时间，其余情况使用报告生成时间。

以下为虚构条目的文字示意；富文本渠道中的新闻标题可点击打开原文：

```text
TrendRadar · 当日汇总
09-06 · 截至 14:35 · 展示 1 条

热榜

人工智能 · 展示 1／匹配 15 条

1. 示例新闻：模型与芯片更新
科技来源 · 今日最高第 3 · 采集命中 6 次 · 观测 08:10–14:30
```

同一条目的当前模式辅助信息可以是：

```text
科技来源 · 当前第 8 · 较上次上升 4 位
```

增量模式可以是：

```text
科技来源 · 本次第 8 · 首次发现 08:10
```

RSS 使用 `发布 09-06 13:20` 表示文章发布时间，并按配置时区转换；不显示热榜排名或采集次数。按来源分组时，来源放在组标题，条目保留命中的主题。

## 数量与范围

- 报告头统计本次展示的新闻；同一来源、同一链接在主区和新增区重复出现时只计一次。独立展示单独计数。
- 分组受到条数上限限制时显示“展示 X／匹配 Y 条”。独立来源使用“展示 X／共 Y 条”。
- 独立展示热榜标注“当前快照”，RSS 标注自己的数据范围。AI 标注实际分析模式，例如“AI 解读 · 当日数据”，可以与报告模式不同。
- 数据总量、来源成功数、失败来源和版本提示放在通知末尾，不占用新闻开头。

## 各渠道的呈现

| 渠道 | 输出格式 |
| --- | --- |
| Telegram | HTML 标题链接与加粗分组，关闭网页预览 |
| 飞书 | 卡片 Markdown；文本接收端使用纯文本 |
| 钉钉 | Markdown |
| 企业微信 | 依 `msg_type` 使用 Markdown 或纯文本 |
| Slack | 原生 mrkdwn |
| Bark、ntfy | Markdown，通知标题带报告模式、时间和页码 |
| 通用 Webhook | 可选 Markdown 或纯文本 |
| 邮件 | HTML 正文与完整的纯文本备选正文 |

纯文本正文在每条新闻后保留完整原文链接。长消息优先按完整条目拆分，续条带页码、区域、分组名称和原编号；极长标题或分析段落才进一步拆分。Telegram 按解析后的文字长度计量，其他渠道按各自的正文或请求体上限计量。无法在上限内保留完整链接时，该渠道报告失败，其余渠道继续处理。

## 通用 Webhook 配置

默认保持 Markdown。接收端不支持 Markdown 时，在 `config/config.yaml` 中设置：

```yaml
notification:
  channels:
    generic_webhook:
      format: "text"  # markdown 或 text
      payload_template: '{"title":"{title}","content":"{content}"}'
```

也可设置环境变量 `GENERIC_WEBHOOK_FORMAT=text`。Docker Compose 可在其 `.env` 中设置同名变量，GitHub Actions 可设置同名 Secret；未设置时使用 YAML 配置。此选项统一作用于已配置的通用 Webhook 账号。模板中的 `{title}`、`{content}` 只替换一次，新闻原文中相同的字面文本会保留。
